# 글 작성 규칙

## 1. 글 구조

설정 가이드나 절차를 정리하는 포스트에만 적용한다. 모든 포스트에 일괄 적용하지 않는다.

```markdown
# 개요
(excerpt과 동일한 한 줄 요약)

# 정리
## 1. 첫 번째 단계
## 2. 두 번째 단계

# 참고
- <https://example.com>
```

## 2. 언어별 섹션 제목

| 섹션 | 한국어 | 영어 | 일본어 |
|---|---|---|---|
| 개요 | `# 개요` | `# Overview` | `# 概要` |
| 정리 (절차/설정 가이드) | `# 정리` | `# Steps` | `# 手順` |
| 정리 (개념 설명) | `# 정리` | `# Summary` | `# まとめ` |
| 참고 | `# 참고` | `# References` | `# 参考` |

## 3. 포스트 유형별 구분

### 3.1. 가이드 포스트

설정 가이드, 절차 문서 등은 위의 글 구조(개요/정리/참고)를 따른다.

### 3.2. 경험 포스트

경험 공유나 이야기 형식의 포스트는 콜론(`:`)과 bullet point를 과도하게 사용하지 않고 자연스러운 서술체로 작성한다.

## 4. 작성 스타일

- 이미지에 `max-width`를 지정할 때는 `min(원하는값, 100%)`를 사용한다 (예: `style="max-width: min(400px, 100%);"`)
- 이미지가 여러 장이고 개별 설명이 중요하지 않은 경우 Minimal Mistakes 갤러리로 묶는다. Front matter에 `gallery_xxx` 배열을 정의하고 본문에서 `{% include gallery id="gallery_xxx" caption="설명" %}`으로 삽입한다
- 코드 예제가 실제 저장소의 소스 코드를 참조하는 경우 개행과 버전을 실제 소스와 일치시킨다
- ASCII 다이어그램에서 박스를 구성하는 모든 라인(`|`, `+`)의 문자 수를 통일한다. 박스 외부로 연결선이 나가는 라인은 예외이다
- 수학 관련 태그는 `Mathematics`를 사용한다 (`Math` 아님)

## 5. 참고 섹션 규칙

- 링크는 타이틀 없이 URL만 표기한다 (예: `- <https://example.com>`)
- URL은 알파벳순으로 정렬한다
- 현재 접속이 가능한 링크만 포함한다
